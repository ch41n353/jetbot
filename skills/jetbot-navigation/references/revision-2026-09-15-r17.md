# Revision 17 — asynchronous Sol shadow perception

2026-09-15, America/Los_Angeles. Source skill updated locally; installed skill
copy has not been synchronized. No GitHub push.

`local_nav/async_scene.py` uses GPT-5.6 Sol, reasoning none, the tuned pixel
prompt in `local_nav/prompts/sol_scene.txt`, and strict scene JSON. No tool calls
are supplied to Sol. A local harness owns scheduling; the object mission remains
the only motor-command owner. Enable with `"sol_shadow": true` in `plan_mission`.
The mission process must inherit OPENAI_API_KEY and have API network access.
Default missions make no new model calls.

One daemon network worker at a time, no queued images, minimum four seconds
between request starts, at most 30 requests per mission. Worker performs JPEG
encoding and HTTP; the control loop copies a frame and polls without waiting.
Existing motor leases, sensor/power/clearance checks and mission limits remain.
Completion closes the mailbox without waiting on the request; an already-sent
request may still finish and incur cost, but cannot actuate or restart a mission.

Capture timestamps, measured pose, aligned frame attitude and control generation
are frozen with the image. Returned floor contact is projected at capture
attitude, transformed into mission coordinates, then expressed at current pose.
Replies older than eight seconds, mismatched generations, over 60cm displacement
or 15 degrees heading change, malformed contacts and invalid floor projection
are rejected as advisory observations. These limits are experimental heuristics.
IMU-only acceleration integration is not used for translation.

This is SHADOW mode: neither targets nor obstacle maps nor routes are modified.
Model obstacle boxes are logged, not treated as verified free space. Active
missions still need an inspected static map and a locally tracked target.
Events identify `sol_request_started`, `sol_shadow_response`, and errors; remote
request counts now include these Sol calls. Late pending replies may not appear
in the final event log. Controller health checks remain the source of motion
permission. No general moving-obstacle avoidance or moving-camera VLM accuracy
has been demonstrated.

Validation: five async tests cover delayed translation/rotation, rejection,
nonblocking polling, immutable snapshots and shutdown. Existing capture and
mission safety tests pass (13 tests). Real Sol request on a saved 640x480 image
completed in 6.43s while a synthetic 20ms loop completed 311 ticks; maximum poll
duration was 0.99ms. This does NOT measure real camera/control-loop load.
Artifacts: `reports/async-sol-2026-09-15/api-smoke-network.json`.
The initial sandbox-restricted request failed with URLError and was retained as
`api-smoke.json`; authorized network retry succeeded. No robot motion this turn.
