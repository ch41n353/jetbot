# Revision 18 — deterministic search with Sol recognition

2026-09-15. User requested full-room search: scan 360 degrees first, then search
along walls. Deterministic coverage owns search; Sol is the visual recognizer.
This supersedes the briefly proposed model-selected search-action design.

`local_nav/sol_search.py` implements:

- Measured clockwise turns up to 30 degrees until 360 degrees within 1.5-degree
  turn tolerance, unless a target is recognized earlier or clearance blocks it.
- Remember observed headings and accumulated actual rotation at each station.
- Generate clockwise perimeter stations 35cm inside supplied rectangular room
  bounds, at spacing no greater than 40cm. Room bounds are external measured
  geometry, not inferred from the camera's current free-space rectangle.
- Use existing local SE(2) A* and full-chassis sweep checks to select the least
  costly reachable perimeter entry, then follow perimeter order, skipping
  unreachable stations. Skipped stations are not marked observed.
- Ask Sol (`gpt-5.6-sol`, reasoning none) for scene recognition. False visibility
  continues deterministic searching. Model motion fields cannot override policy.
- Once recognized, prepare and preview a checked object approach and hand it to
  the local object controller. Only its arrival result counts as completion.
- Cancellation epochs, measured turn translation, accumulated uncertainty,
  battery and sensor guards remain. Unknown map extent is not free space.

Use with a fresh anchored plan containing `session_id`, `control_epoch`,
`image_path`, `captured_monotonic`, `target_label`, `preview_path`,
`inspected_free_rectangle_cm`, `obstacle_rectangles_cm` and either
`room_bounds_cm` or explicit `search_stations_cm`. Optional standoff defaults25cm,
target radius7cm. Existing scoped floor alignment must NOT be reused after
more than10 degrees of search heading change; the harness refuses that case.
No persistent SLAM or automatic room-map construction is supplied.

Motor-free check:
`/usr/bin/python3 local_nav/sol_search.py PLAN.json`

Under `maneuver_session.py`, dispatch a cancellable child using
`{"command":"execute","plan":"/absolute/PLAN.json","search":true}`.
The supervisor must already be armed within the user's authorization, and the
plan must reference the current inspected scene. The worker owns the entire loop;
Astra is not called at each action. Existing supervisor stop/shutdown remains.
Preview files update before each action; events expose each Sol request, local
choice, preview and completion. No GitHub push.

Limits:20 recognition requests,300seconds,120cm measured accumulated travel,
2cm/4-degree accumulated pose uncertainty. This bounds an experiment, not a
guarantee of whole-room coverage. A blocked search reports a limit and retains
coverage history rather than claiming the object does not exist. Stationary
recognition still waits for Sol between search actions in this first version;
the async shadow observer is a separate mode. No claim of fully overlapped
search inference or verified general obstacle avoidance.

Validation:11 search tests include a simulated absent->turn->visible->approach
harness run, cancel-during-inference, full rotation before relocation, perimeter
inset/order, conservative coordinate transforms, ignored model motion fields,
and supervisor dispatch. Seven supervisor and five async tests pass. Real API
replay used two saved images: absent duct tape led to deterministic scan_right
(4.26s), near duct tape led to approach (4.31s). Synthetic map used for that
replay; no motors. See `reports/deterministic-search-2026-09-15/recognition-replay.json`.
