# Revision 19 — scalable search boundary and final-view recognition

2026-09-15. See the complete architecture and validation limits at
`reports/search-architecture-2026-09-15/README.md`.

- `sol_search.py` now recognizes the stopped final view even after accumulated
  pose uncertainty blocks further motion. Search-only recognition can complete
  without a valid global pose. Approach/more search motion remains blocked.
- Search event history is frozen rather than retaining mutable coverage lists.
- `spatial_turn.execute_turn` accepts an optional validated power value; default
  remains.14. One live retry used.15 after an.14 right-turn stall. Existing stall,
  timing, IMU, power and clearance guards remain.
- `search_graph.py` is a persistent motor-free planner for submaps, doorways,
  frontiers and observation coverage. It uses versioned corridor evidence,
  shortest-path search, checkpoint/resume, and explicit relocalization requests.
  No global odometry uncertainty reset and no room-count-dependent representation.
- New graph functionality is not a live SLAM backend. The static rectangle
  harness remains limited. Do not claim autonomous multi-room operation.

Evidence:14 harness tests and7 graph tests pass. Recorded six-turn uncertainty
was4.15deg yaw sigma and.77cm position sigma; actual Sol final-image recognition
found the other robot. New handling is validated in motor-free regression and
recorded replay, not a new powered run. The100-room test is synthetic graph
planning, not robot travel. No new motion or GitHub push during this revision.
Installed skill copy remains older; repository source records these changes.
