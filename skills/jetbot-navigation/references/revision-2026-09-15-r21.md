# Revision 21 — autonomous Sol loop, continuous turns, and dashboard

2026-09-15, America/Los_Angeles. Changes remain local; no GitHub push.

`sol_search.py` now owns the complete semantic-search loop after one supervisor
handoff. GPT-5.6 Sol supplies strict scene recognition only. Deterministic local
code owns coverage, candidate selection, retained-map sweep checks, SE(2) A*,
controller dispatch, arrival rules, call/action budgets, and final versus
intervention handoff. `recognition_every_actions` controls a bounded recognition
cadence. `AsyncScene` permits one context-bound request in flight with no stale
image backlog. API output never directly commands motors or expands free space.

The search process writes atomic checkpoints after decisions and completed
actions. `resume_checkpoint_path` can continue only an eligible action-complete
checkpoint after exact target/session/control-generation checks, an anchor no
older than 120 seconds, and visual pose revalidation. Final, failed, cancelled,
and intervention checkpoints do not auto-resume.

`continuous_turn.py` implements signed turns through 180 degrees in one process
using IMU yaw/rate and generation-bound `motors_hold`. It retains power, health,
tilt, rate, wrong-direction, stall, overshoot, renewal, timeout, cancellation,
and final-zero guards. Braking uses measured rate plus bounded command latency
and deceleration. Final success requires quiet settled IMU evidence. Autonomous
scan turns default to this controller while retaining the full static-map sweep
precheck. Search then performs stopped post-turn visual translation estimation,
camera/IMU yaw agreement within three degrees, and a measured-body map check
before adopting the new pose. Pulse turns remain opt-in. This continuous path is
not yet powered-validated.

The live pre-integration Advil trial made two Sol calls and completed one 30.47
degree pulse turn before the next turn stopped on the unchanged 180 ms image
deadline. Two CPU-heavy test runs were active on the Jetson Nano during powered
motion and are the likely scheduling cause; Sol had completed before the turn.
No deadline was relaxed. The service was shut down with motors zero. Pack voltage
dipped to 11.328 V, below the 11.4 V warning threshold but above the 10.8 V hard
stop. Recharge before another powered acceptance run.

`evaluate_autonomous_stack.py` and `test_autonomous_stack_simulation.py` cover
nine deterministic motor-free scenarios: visible/absent target, blocked cable,
API timeout/retry, stale response, cancellation, low power, four-room checkpoint
resume, and final approach. The approach simulation reached an estimated 18.66
cm for a 20 cm standoff, with zero intermediate model calls, zero simulated
clearance violations, and final motors zero. Forty-seven combined component and
simulation tests passed. Mapping, localization, API timing, and plant behavior
are synthetic in this layer.

`local_nav.dashboard.server` provides a loopback-only browser console. It owns
one `maneuver_session` process and exposes target start, stop, stopped-only reset,
latest RGB, the current sandboxed trajectory preview, live Sol/policy/controller
events, power/sensor/motor telemetry, result, and checkpoint. It tails the
worker event journal while the mission runs. The browser receives neither the
API key nor motor-socket access. Start it motor-free with:

```bash
/usr/bin/python3 -m local_nav.dashboard.server
```

Authorized motion requires the explicit `--enable-motion` launch flag. Seven
focused dashboard tests and 46 combined dashboard/continuous/async/search/
simulation tests passed. See `local_nav/dashboard/README.md` and
`docs/SEARCH_AND_NAVIGATE_STACK.md`.
